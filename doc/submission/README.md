# Oilracle: technical guide

Oilracle produces daily rolling WTI price forecasts, predictive distributions and tail-risk estimates. The supplied final results use parameters fitted with information available by 30 September 2026 and evaluate October targets without further tuning.

All paths and commands below are relative to the extracted `project/` directory. Editable slides are in the sibling `Presentation/` directory.

## Setup and review

Use Python 3.12 or newer and `uv`. The checks below were verified with Python 3.14.7. The lockfile records exact dependencies; installation requires internet access. The Windows/Linux lock uses CUDA 12.8 PyTorch packages, but these review commands do not require a GPU.

```powershell
uv sync --locked
uv run python -B scripts/audit_submission_data.py
uv run python -B -m pytest -q m3_ml/tests/test_fusion_v6.py
uv run python -B -m m4_reports.plot_final_forecast
uv run python -B -m m4_reports.plot_historical_forecast
```

The data audit checks source hashes, table consistency and publication alignment. The seven targeted tests cover label availability, target-independent predictions, quantile ordering, width limits and sealed inputs. Plot commands read saved forecasts, verify them and regenerate figures without training or model selection.

`m4_reports/final_strategy_manifest.json` identifies the sole final forecast and its integrity hash. Its output directory is:

```text
m3_ml/fusion_v6/outputs/frozen_october_2026/rolling/
```

| Output | Contents |
| --- | --- |
| `forecasts.csv` | Daily rolling price forecasts, quantiles and risk estimates |
| `metrics.csv` | October scores and baseline comparisons |
| `historical_point_metrics.csv` | Historical point-forecast scores |
| `historical_risk_metrics.csv` | Historical interval and distribution scores |
| `delivery_scope.json`, `delivery_audit.json` | Evaluation scope and integrity checks |
| `figures/` | October figures regenerated by the plotting command |
| `history_review/` | Regenerated historical figures and metric tables |

## Source map

| Directory | Purpose |
| --- | --- |
| `data/` | Local source snapshots, processed tables and rebuild inputs |
| `scripts/` | Data preparation, validation and audit |
| `m1_time_series/` | Time-series regression and VECM |
| `m2_seasonality/` | Monthly seasonal decomposition and forecast bridge |
| `m3_ml/lstm/` | Sequence forecasting |
| Other `m3_ml/` modules | ML point, distribution, risk and fusion models |
| `m4_reports/` | Final forecast routing, evaluation and chart code |

Saved intermediate outputs and earlier model stages support the final model's dependencies and research traceability. Use the final manifest to select the delivered results. Model directory suffixes are internal identifiers.

## Optional data rebuild

The included snapshots support an offline rebuild into a separate directory:

```powershell
uv run python -B scripts/prepare_data.py --output-dir .local/data_check
uv run python -B scripts/validate_prepared.py --output-dir .local/data_check --check-rerun
uv run python -B scripts/audit_submission_data.py --rebuilt .local/data_check
```

For the broader Python checks, run `uv run python -B -m pytest -q m3_ml/tests m3_ml/lstm/tests`. Full retraining is separate from reviewing saved results and can be expensive; work in a separate copy to preserve the sealed outputs. The frozen R entry points, `m1_time_series/for_test_set.R` and `m2_seasonality/seasonality.R`, require R with `forecast`, `fGarch`, `vars`, `urca`, `car`, `sandwich` and `lmtest`. Exploratory R scripts list additional packages in their imports.
